# 派发补偿回移到 1.21.1 main

来源：1.20.1 的派发回执与精确回收设计。适配 main 的 PendingOutputBuffer 接口，保留 main 原有适配器集合。

- 预检失败或明确零接收：返回失败，输入仍属于 CPU。
- 实际插入产生明确回执：按目标、种类、数量记录；部分插入不再运行完整提交回调。
- 提交失败且全部已投入物料被确认取回：返回失败，由 CPU 保留完整输入。
- 只取回部分物料或后续回收异常：只把确认取回的物料与未尝试投入的物料保存到待交付缓冲；继续返回已接收，阻止 CPU 重复退款。
- 插入调用抛异常或返回非法数量：当前那份物料的归属未知，不能推定为零接收；只处理先前明确回执和后续未尝试输入。
- MA 注魔与觉醒祭坛接入激活确认和精确槽位回收；只有确认祭坛未激活且槽位物品/组件/数量均吻合才取回。
- 没有精确回收回调的适配器继续保留机器中的物料并记录错误。此机制不承诺能追回任意第三方异常中的物料。
- 待交付物品已入缓冲后，宿主保存通知失败不再向 CPU 抛出可触发重复退款的异常。

验证：Java 21、Minecraft 1.21.1 / NeoForge 21.1.230，82 项 JUnit 全通过，包含 10 项真实 AE2 类型上的补偿故障注入；完整 build 通过。MA IActivatable 的 activate/isActive 签名已用目标模组 JAR 核对。本轮没有运行所有第三方模组的游戏内组合测试。
