# LTPP 1.20.1-alpha 回移记录

范围：仅架构和代码；适配器注册、机器目录、支持模组集合、产品资源/配方均保持 1.20.1 基线内容。1.21.1 的 Astral Sorcery 新适配不加入本分支。

## 完成的回移

- 接入 Thunderbolt 的 IBatchCraftingProvider，普通纯虚拟配方每条通道每刻最多 64 份。Avaritia 工作台/锻造、EC 工作台及灵魂火保留原有配方逻辑；带机器提交副作用的结果拒绝进入多份缩放路径。
- 批量与单次派发共享通道限额；阻塞模式、合成锁、超频和包装样板保留其既有单次语义。输入模板只读，能量与产物按确认接收份数计算。
- 后续通道异常不能撤销已经接收的批次；输出采用逐笔接收回执，部分刷新成功后发生异常不会重放早先已交付的产物。数量超过 long 的累积总量分块保存。
- 提取 14 个可选模组反射访问类，保留 Forge 版本的类名回退、反射启动诊断和失败处理。
- 公共 IngredientAssignment 使用原有多项式增广路匹配；统一网格放置、工作台公共操作和 Cucumber 完整槽位访问。保留 Avaritia/EC 各自原生余料、阶数与匹配顺序差异。
- Mekanism 配方绑定按控制器真实配方类型筛选与排序端口，拒绝不匹配的气体；保留旋转冷凝双向合同和配方重新加载身份检查。适配 10.4 的 Gas API、泛型 ChemicalStack 参数及原生 Recipe。
- 使用这次回移实际生成的 AE2LT 2.1.0 和 Thunderbolt Forge 2.0.0 本地 Maven 产物。

## 保留的 Forge 保护

保留模式/资源重载失效、派发补偿、输入/产物归属记录、空闲检测、独立产物轮询和清空样板槽时的待交付产物。main 中会删除这些保护的简化没有照搬。

实体机器的批量投入队列没有替换 Forge 的派发路径：MekMM 仍逐次执行带投入回收和产物归属回调的事务，采用已回移的配方端口绑定。该选择保留现有的加工/回收合同；多份批量加速只覆盖上述纯虚拟路径。

## 原生验证

Java 17、Minecraft 1.20.1 / Forge 47.4.10、AE2 15.4.10。

```sh
# 同级 Thunderbolt 和 AE2LT 已 publishToMavenLocal 后：
./gradlew test build
./gradlew -I scripts/batch-test.init.gradle runGameTestServer
```

- 258 项 JUnit：含随机匹配穷举对照、通道限额、派发异常/补偿、输出保存与既有适配器回归。
- 5 项原生 GameTest：EC 接收 64/70 份及 64 个空桶余料；真实 Thunderbolt 单次 CPU 操作派发；后续通道抛异常时只退回 6 份；NBT 恢复、清空后的产物保留、下一刻锁/阻塞控制；Mekanism 双气体排列与旋转冷凝双向/错误方向拒绝。
- 运行用例使用 EC 6.0.10、Cucumber 7.0.16、Mekanism 10.4.16.80 和 Applied Mekanistics 1.4.3。测试依赖只由独立 init 脚本引入，测试夹具不会进入发布 JAR。
- 没有实测所有可选模组的所有组合；反射结构整理由编译、既有单元回归和上述真实联动覆盖。

派发补偿另已适配到 1.21.1 本地 main，见该分支 docs/dispatch-compensation.md。
