# Forge 1.20.1 Alpha 合并记录

2026-11-07：以 1.20.1 的 7463c70 为基线，合入 1.20.1-alpha 的 13e61ab 及其四个独有提交。基线已经包含部分批量派发与 EC 实时配方保护，因此冲突解决以当前实现为基础补齐独立改进。

## 保留的产品与兼容性合同

- 模组版本保持 1.2.2-beta2，依赖保持 AE2LT 2.1.2、Thunderbolt 2.0.3、AE2 15.4.10，使用 Java 17 / Minecraft 1.20.1 / Forge 47.4.10。
- 保留现有机器注册、联动目录、谐振布局、扩展供应器、原生核心订单、自然灵气及女仆自动化、产品资源和配方。
- EC、Avaritia 等原有无上限虚拟合成继续使用当前容量合同；实体批量和有界虚拟通道继续共享其每刻额度。阻塞、合成锁和包装样板仍使用现有单次语义。
- 保留当前 planBatchWithBinding、onBatchAccepted 和 refreshBatchOwnership：先确认产物归属再投料，已回收的额度不会由恢复流程重新创建。

## 合并的独立改进

- 机器插入严格校验回执。空余量、负余量、超过投入量的余量以及插入后抛错均进入既有不确定投入处理，不能当作零接收而重试或退款。
- 虚拟多份缩放要求 VirtualCraftingResult.isPure()。保留当前精确数量队列，加入逐笔交付回执，先扣除已确认部分再处理下一笔；旧刷新接口与新接口共享时钟。
- 已接收的虚拟产物先进入持有队列，再执行保存、能量扣除和通知。后续回调失败不能让 CPU 退回已经接收的份数；接收前的准备失败只退回未转移归属的输入。
- 将 12 个可选联动的反射访问部分从适配器中提取，保留当前 Forge 方法签名、类名回退和机器行为。Ender/Flux Crafter 继续复用已有 EcCrafterSupport，没有加入重复访问实现。
- 共享网格放置、原生工作台操作和 Cucumber 完整库存访问。材料匹配继续使用增广路，预计算候选并按候选数量稳定排序，保留 Avaritia/EC 各自的配方和余料语义。
- Mek 配方方法解析选择唯一且最具体的兼容重载，并复用 ReflectionSupport 的可访问方法缓存；保留当前控制器配方类型、输入/输出数量、旋转冷凝方向和重载身份校验。

## 存档与回收

- 当前输入队列和虚拟产物的 NBT 格式保持兼容。输入队列额外读取旧 Alpha 的 batch_inputs、ports、uncertain 和 owner，包括旧 GenericStack 编码。
- 旧 ae2ltpp:mekmm 路由转换为当前 MekMM 适配器标识。当前格式优先于遗留旧数据；写回时移除旧标签，清空或回收后不会从旧标签重新生成材料。
- 不可读的旧控制器归属不能授权继续投料；已经移除的产物归属不会被盲目重建。不确定投入保持隔离，不能自动回收。
- 拆除沿用 AE2 的实际掉落调用链，只回收一次已知未投入材料。新增显式输入队列转移方法复用现有快照与清空机制。

## 验证

通过现有发布依赖下载脚本准备对应 Forge 产物后，执行：

    .\gradlew.bat -I .github\release-dependencies.init.gradle test build
    .\gradlew.bat -I .github\release-dependencies.init.gradle -I scripts\batch-test.init.gradle runGameTestServer
    python .github\scripts\test_release.py
    python .github\scripts\test_forge_release_repositories.py

- 单元测试：387 项，0 失败、0 错误、6 跳过；构建通过。
- 发布脚本：12 项检查通过；原始与映射依赖仓库的解析检查通过。
- 原生 GameTest：13 项全部通过，包含部分投入、重载/清空/拆除、同刻后续通道异常、真实 MekMM 生产与精确产物回收。
- 原生批量测试使用独立 batchTest 源码集和运行目录；测试夹具不进入发布 JAR。使用 EC 6.0.10、Cucumber 7.0.16、Mekanism 10.4.16.80、Applied Mekanistics 1.4.3 和 MekMM 官方 CurseForge 文件 7884538。
