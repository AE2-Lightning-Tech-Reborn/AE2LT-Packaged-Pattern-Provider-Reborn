# 自然灵气封包

验证环境：Minecraft 1.21.1、NeoForge 21.1.230、Nature's Aura 41.10、Patchouli 1.21.1-93、AE2LT 2.1.2-beta、Thunderbolt 2.0.3-beta。

## 行为

- 自然祭坛：绑定本体，保留真实灵气消耗、合成时间和原位催化方块。样板填写一份消耗原料和精确产物。原版优先充能的灵气容器不作为祭坛配方输入接受。
- 森林仪式：绑定任意一个木基座，布局需能唯一确定中心且有足够的空基座。树苗必须写入样板。金粉已有数量加样板提供数量必须恰好等于原版 16 个位置；只补空位，不覆盖其他方块，也不丢弃多余输入。树木仍需自然生长或外部骨粉装置。
- 供奉台：样板支付原料和一个原版启动物，直接触发原版供奉逻辑。启动物以机器中持久化的物品栈保存，提供给原版判断的临时实体不加入世界；磁铁、吸物器及实体加入事件无法取得它。正常手动供奉不改变。
- 封包产物在机器中持久化暂存；开启供应器自动回收后进入回收队列。回收关闭时保留成品，拆机时掉落已生成的成品。供奉台的原版额外黑色染料照常返回。
- 森林仪式由原版消耗材料、树木和金粉。原版取消仪式时不生成产物、不凭空退还已消耗材料；未消耗材料留在原位，并释放封包占用状态。

三个封包都通过对应原版机器加工基础封包核心获得，制作配方、中英文名称和游戏内指南随包提供。目标模组未安装时不注册运行入口，不显示这三种封包，也不加载它们的配方。

## 实现边界

每个目标执行一份真实配方；没有绕过时间、灵气、启动物或世界耗材的虚拟批量合成。配方在绑定时匹配，发配使用缓存候选并复核原版当前选择；森林结构查找限制在原版基座和金粉位置。

生产代码通过反射和可选 Mixin 接入，不包含自然灵气类或 JAR。三个完成钩子只捕获已发配给该机器的原版成品。额外修复仅作用于封包管理的森林仪式：41.10 原版保存 `RecipeHolder.toString()`，这里保存实际配方 ID，并在方块实体获得世界后恢复未完成的配方。

## 复现验证

使用 Java 21。先按仓库 README 配置 AE2LT 与 Thunderbolt 的本地构建依赖，再运行：

```sh
bash ./gradlew --no-configuration-cache \
  -I scripts/natures-aura-test.init.gradle \
  -PppNaturesAuraJar=/path/to/NaturesAura-41.10.jar \
  -PppPatchouliJar=/path/to/Patchouli-1.21.1-93-NEOFORGE.jar \
  test runGameTestServer jar

bash ./gradlew --no-configuration-cache \
  -I scripts/natures-aura-test.init.gradle \
  -PppNaturesAuraAbsent \
  runGameTestServer
```

原生测试覆盖三种核心配方、真实灵气不足、催化条件、同键输入输出、发配补偿、金粉三种供给方式、八个基座的绑定、真实树苗生长、仪式中途连续保存重载、取消时的物品守恒、无掉落物供奉、原版额外产物、拆机保护，以及真实无线供应器投料与回收。另有不安装目标模组的启动检查。测试类、测试配方和结构不会进入生产 JAR。
